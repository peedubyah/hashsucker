# Audit + Implementation Report: Provider-Agnostic Evidence Confidence Projection

**Scope:** Introduce a small, deterministic, side-effect-free confidence
projection above durable identity. Answers:

> "Given the observations we have for this release/candidate, how strong is our
> belief that it is worth considering/probing?"

This is **NOT** current provider availability and **NOT** durable identity.
Confidence may change what we believe about an identity. It may never change
what the identity is.

## 1. Evidence taxonomy (provider-agnostic)

The projection consumes opaque evidence items with shape:

```js
{
  kind: <string>,         // see enum below
  source: <string>,       // opaque source tag
  observedAt: <number>,   // ms epoch
  generationId?: <string>,// for DMM items, opaque gen id
  state?: <string>,       // for provider items: 'cached' | 'uncached' | 'error' | 'unknown'
  ttlMs?: <number>        // optional TTL override
}
```

Kinds (no others accepted):

| kind | family | polarity | default TTL |
|---|---|---|---|
| `DMM_HISTORICAL`        | dmm         | positive    | 30 d |
| `DMM_REPEATED`          | dmm         | positive    | 30 d |
| `PROVIDER_HISTORICAL`   | provider    | positive    | 24 h |
| `PROVIDER_FRESH_POSITIVE` | provider  | positive    | 1 h |
| `PROVIDER_FRESH_NEGATIVE` | provider  | negative    | 1 h |
| `PROVIDER_STALE`        | provider    | ambiguous   | 0 (always decayed) |
| `ATTRIBUTE_HISTORICAL`  | attribute   | positive    | 7 d |
| `MEDIA_ASSOCIATION`     | media       | positive    | 7 d |
| `SOURCE_LISTED`         | source-list | positive    | 7 d |

Provider-agnostic means: the projection does not call out to any provider
and does not know the names of any provider. Provider observations are
pre-classified into one of `PROVIDER_HISTORICAL`, `PROVIDER_FRESH_POSITIVE`,
`PROVIDER_FRESH_NEGATIVE`, `PROVIDER_STALE` by the caller.

### Classification axes (per spec)

| axis | mapping |
|---|---|
| historical vs current | DMM items are historical; provider items are current. Decay turns them stale. |
| authoritative vs heuristic | provider items are authoritative; DMM/attribute/media/source-list are heuristic. |
| release-level vs file-level | file_index_key is part of identity, NOT of evidence classification. The projection is identity-agnostic. |
| positive/negative/ambiguous | see polarity column above. |
| combinable | yes — with the precedence rules below. |

### Existing sources inventoried

| existing source | class | notes |
|---|---|---|
| `dmm_source_observations` | `DMM_HISTORICAL` + `DMM_REPEATED` | many-to-many provenance from prior slice |
| `provider_observation_current` (state=cached) | `PROVIDER_FRESH_POSITIVE` | fresh = `freshness==='fresh'` |
| `provider_observation_current` (state=uncached/error) | `PROVIDER_FRESH_NEGATIVE` | fresh only |
| `provider_observation_current` (state=unknown) | `PROVIDER_HISTORICAL` | proves we probed, no result |
| `provider_observation_current` (stale) | `PROVIDER_STALE` | past `expires_at` |
| `release_attributes` | `ATTRIBUTE_HISTORICAL` | local regex/predictor — local evidence, NOT provider truth |
| `candidate.sources` (JSON array) | `SOURCE_LISTED` | per-source `lastSeen` |
| `candidate_media` | `MEDIA_ASSOCIATION` | candidate ↔ media link |

Sources NOT touched (per spec):
- `provider_observation_events` is read indirectly via `getProviderObservations`/`getProviderObservationHistory` and pre-classified before being passed to the projection.
- `corpus_observations` (the older `evidence-projection.js` log) is not in this projection's taxonomy. It is the storage tier; the projection is the compute tier above it. (Future work may bridge them.)

## 2. Projection dimensions

| dimension | range | meaning |
|---|---|---|
| `availabilityPrior` | [0, 1] | historical evidence the candidate is worth probing |
| `identityConfidence` | [0, 1] | how well-evidenced the identity is (multi-source, multi-generation) |
| `corroboration`      | [0, N] | count of independent source-type families that have observed this identity |
| `freshness`          | [0, 1] | decay factor based on `now − mostRecentObservedAt` |
| `freshProvider`      | null \| `'positive'` \| `'negative'` \| `'ambiguous'` \| `'stale'` | current provider observation, if any |
| `reasons`            | string[] | enumerative, sortable, no magic-number language |
| `evidence`           | Array    | the (deduped, sorted) input observations that contributed |
| `evidenceCount`      | number   | length of `evidence` |

**Critical property:** no single scalar may masquerade as durable
availability state. Callers that need a scalar must compose it explicitly
from these dimensions. The projection refuses to do that for them.

---

## 3. Precedence rules (applied in order; last-write-wins per dim)

1. **Fresh provider outranks historical prior for current-period
   availability.** `PROVIDER_FRESH_*` sets `freshProvider` and is reported
   in `reasons`, but is **not folded** into `availabilityPrior`. The
   historical DMM/provider reasons are preserved so that callers can
   reason about trajectory, not just current snapshot.
2. **Independent generations raise identity confidence.** Two DMM
   observations from the same `generation_id` count as one; observations
   from distinct `generation_id`s are independent. The
   `dmm-seen-across-N-generations` reason enumerates the count.
3. **Multiple independent source-type families raise corroboration.**
   `corroboration` is the count of distinct families (dmm, provider,
   attribute, media, source-list) that have at least one observation.
4. **Stale evidence decays.** `decayFactor(ageMs, ttlMs)` is exponential
   with half-life `FRESHNESS_HALF_LIFE_MS = 7 days`; past `ttlMs` the
   factor tapers linearly to 0 over the next 2× `ttlMs`.
5. **Missing evidence yields null/0, never negative.** `freshProvider`
   is `null` when no fresh provider observation exists; this is unknown,
   not zero.
6. **Local regex/predictor ≠ provider truth.** `ATTRIBUTE_HISTORICAL` is
   local evidence. It contributes to `identityConfidence` and
   `corroboration` only. It never sets `freshProvider`. The
   `no-fresh-provider` reason fires whenever corroboration > 0 but no
   fresh provider observation is present.
7. **No single scalar.** Output is a structured object; the projection
   refuses to collapse to one number.

## 4. Weights (isolated, documented, simple)

Documented in the module header. All values are isolated in a single
comment block; all callsites are reachable from one file.

| contribution | value | cap | reason |
|---|---|---|---|
| first DMM observation | +0.20 × decay | 1 (overall) | DMM is a non-authoritative, large-scale historical index. One sighting is a weak-but-useful prior. |
| additional independent DMM generation | +0.10 × decay | +0.30 total | Repeated sightings across gens reinforce the prior. |
| provider historical hit | +0.20 × decay | (shared cap) | Real provider hit — stronger than DMM, weaker than current. |
| attribute parsed | +0.20 (one-shot) | 1 | Proves a parser understood the title — modest identity signal. |
| media association | +0.10 (one-shot) | 1 | Corroborating family. |
| source listed | +0.05 (one-shot) | 1 | Weak but free corroboration. |
| base if any evidence | +0.10 | 1 | Reward existence, not silence. |
| corroboration bonus | +0.10 × (families − 1) | +0.20 | Reward independent agreement without overcommitting. |
| DMM cross-generation bonus | +0.10 | 1 | Different temporal evidence for same identity. |
| all-evidence-stale penalty | × 0.5 | 1 | When `freshness < 0.5`, identity confidence halves. |

`availabilityPrior` is capped at 1.0. `identityConfidence` is capped at
1.0. No magic numbers — every value is enumerated above.

`FRESHNESS_HALF_LIFE_MS = 7 days` is the only time constant. Picked to
span realistic DMM refresh cadence (weeks) and provider TTL (hours)
without losing either signal.

## 5. Persistence change

**None.** No schema added, no column added, no table added. The
projection is a pure function over a flat evidence array. The
`createConfidenceProjection(cache)` helper reads existing tables via the
existing cache API (`getDmmObservationsForCandidate`,
`getReleaseAttributes`, `getProviderObservations`, `getCandidate`,
`getMediaAssociations`) and feeds them to the pure projection.

This is intentional per spec: "Do NOT persist the derived confidence
yet unless clearly justified. Persist observations; derive confidence."

## 6. Focused proof (8 spec cases + 7 extras)

All tests in `test/confidence-projection.test.js`. All pin `now =
1_700_000_000_000` for determinism.

| # | case | key assertion |
|---|---|---|
| 1 | one historical DMM sighting | `availabilityPrior` modest (~0.196), `corroboration=1`, `reasons` includes `dmm-historical` |
| 2 | repeated DMM sightings across generations | `availabilityPrior ≈ 0.30`, `reasons` includes `dmm-seen-across-2-generations` |
| 3 | two independent historical sources (DMM + attribute) | `corroboration=2`, `identityConfidence=0.40`, `reasons` includes `corroborated-by-2-families` |
| 4 | historical positive + fresh provider NEGATIVE | `freshProvider='negative'`, `availabilityPrior` preserves DMM, BOTH reasons present |
| 5 | historical positive + fresh provider POSITIVE | `freshProvider='positive'`, both reasons present, DMM prior not overwritten |
| 6 | stale provider observation | `availabilityPrior` decayed to < 0.10, `freshness < 0.2`; `PROVIDER_STALE` explicit kind → `freshProvider='stale'` |
| 7 | no evidence | all 0/null, `reasons=['no-evidence']` |
| 8 | shuffled-order determinism | 4 orderings of 6 observations → identical projection |
| +A | fresh positive + stale historical | fresh wins current, historical preserved in reasons |
| +B | ATTRIBUTE_HISTORICAL alone | `freshProvider=null`, `reasons` includes `no-fresh-provider` |
| +C | identity invariance | same obs, different `infoHash`/`fileIndex` → identical output |
| +D | corroboration cap | 4 families → bonus capped at +0.20; `corroborated-by-4-families` |
| +E | empty-cache live helper | `createConfidenceProjection(cache).project('nonexistent', null)` returns no-evidence projection |
| +F | no-evidence identity invariance | two different identities, empty obs → identical projection |
| +G | PROVIDER_STALE excludes positive/negative | `freshProvider='stale'`, `notEqual('positive')`, `notEqual('negative')` |
