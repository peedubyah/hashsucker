# RIGHTMON Stage 3 finalization

**Evaluation date:** 2026-08-23
**Scope:** Deterministic fixture regression boundary only; no runtime/control-plane or acquisition wiring.
**Verdict:** PASS for Stage 3 research and regression-contract exit criteria.

## Decision

The measured Stage 3 contract is:

```text
FTS retrieve all eligible matches
  → preserve exact (infoHash,fileIndex)
  → deduplicate exact releaseKey only
  → rank from static candidate evidence
  → paginate
```

The rejected ordering is:

```text
FTS retrieve
  → truncate to 2000
  → rank
```

The 2000-row pre-rank window changes the winner for 11 of 30 transferred production queries. This is a recall-policy failure, not a fixture-integrity failure. Stage 3 therefore accepts **no truncation before static-evidence ranking** for this measured corpus/query set.

Stage 3 does **not** choose an acquisition target and does not integrate provider availability. Its output is a ranked candidate set based on static evidence. The downstream boundary is:

```text
ranked candidate set from static evidence
  + fresh cache/provider reality
  + fulfillment policy
  = final acquisition decision
```

Provider observation, cache probing, placement, exposure, repair, and fulfillment remain downstream work. A candidate's static rank must not be presented as proof that it is cached, placeable, exposed, or playable.

## Regression boundary

The harness intentionally keeps two implementations separate:

| Mode | Question answered | Database handling | Semantics |
|---|---|---|---|
| Native runtime | “Given this exact corpus snapshot, what does current retrieval do?” | SHA-256 source fixture, copy to a temporary directory, allow normal writable cache bootstrap only on the copy, delete copy | Current `searchReleases()` and `combinedSearch()` parser, fixture-local BM25, runtime quality, tie order, and 2000 window |
| Reference production ranking | “What does the frozen transferred production-ranking contract produce?” | Open source fixture with `DatabaseSync(..., { readOnly: true })` | Quoted prefix-AND FTS, preserved `production_bm25`, documented quality including additional 2160p/x265 bonus, documented tie order |

Reference code lives only in `stage3-fixture-evaluator.js`. Production search and ranking do not import it. The harness does not replace existing unit tests.

## Required semantic explanations

### `Remux`

The current product parser treats standalone `Remux` as structured `source_type = 'Remux'` intent and removes it from FTS, producing wildcard relevance and 23,137 candidates. The reference vectors treat it as the raw prefix FTS term `"Remux"*`, producing 76,437 candidates. The intended current product semantic remains **structured quality/source intent**. Raw-term reference semantics remain frozen evidence. Context-dependent “both” behavior is not introduced in Stage 3.

The manifest's fixture-local winner is `970c5fd8…` at ordinal 1 and score `.664`; the vector's production winner is `0f9d608f…` at ordinal 76,433 and score `.658`. Reference reconstruction selects the vector identity using preserved `production_bm25`. This manifest/vector disagreement is the expected consequence of corpus-dependent BM25 and is kept visible.

### `Subs`

The parser agrees with raw FTS semantics and cardinality is 46,132. The winner changes across both measured phases: fixture-local versus preserved production BM25, and runtime versus documented reference quality. The expected winner is at production Stage 1 ordinal 46,127 and disappears under the cap. This is BM25 corpus scope plus ranking-formula drift plus the retrieval-window regression; it is not a null-index or candidate-count defect.

The manifest records fixture-local `cf9a905f…` at ordinal 1 and score `.656`; the vector records production `50ff6821…` at ordinal 46,127 and score `.654`. Reference reconstruction selects the vector identity. The two artifacts intentionally describe different BM25 scopes rather than one shared winner oracle.

### `My Hero Academia`

Both native and fully reconstructed reference modes select `f60f7f18…`; the vector expects `a895e13b…`. Cardinality and the expected candidate's production ordinal (644) reproduce. No tested BM25/quality phase selects the vector identity. This is an internally frozen vector/expectation conflict with a score conflict (`.538` reconstructed versus `.540` expected), not missing metadata and not parser behavior.

### `Comedy`

Native and reconstructed reference modes select `ef847d51…`. The reference winner score rounds to the vector's `.610`, but preserved production relevance resolves the documented tie order in favor of `ef847d51…`, not expected `618a2f40…`. This is a reference tie/expectation conflict, not cardinality, parser, or cap behavior.

### `Sci-Fi`

Native and reconstructed reference modes select `e5b260b3…`; expected is `021eb702…`. Preserved production BM25 places the expected identity at ordinal 136, not the vector's 130, and the documented reference rank is `.540`, not `.550`. This is a production-evidence/vector conflict expressed through relevance/tie ordering. It is not caused by the 2000 cap.

## Static ranking versus provider reality

The transferred formula contains a `providerAvailability` component fixed at neutral `.5` because fixtures contain no provider observations. That historical field does not change the Stage 3 boundary: Stage 3 evaluates a static-evidence ranked candidate set. It does not fetch, inject, or interpret live cache/provider state, and this finalization does not redesign the production ranker.

Future acquisition work must consume the ranked set and make a separate, explainable decision using fresh authoritative provider observations and explicit fulfillment policy. It may select a lower statically ranked candidate when provider reality or policy requires that outcome. That selection is a downstream acquisition decision, not a mutation of Stage 3 evidence.

## Limitations

- The fixtures contain no live discovery results.
- The fixtures contain no provider observations; provider-related reference inputs are neutral constants only.
- Episode fields exist but episode coverage is sparse, so this does not validate broad TV coverage behavior.
- All fixture releases are DMM-derived; source diversity and changing production corpus statistics are not represented.
- BM25 is corpus-dependent. Fixture-local BM25 is valid for measuring current behavior on this snapshot, while exact production reconstruction requires preserved `production_bm25`.
- The ranking database is a selected union of query neighborhoods, not the complete production database.
- The artifact contract contains known internal conflicts. The harness exposes rather than masks them.
- Latency figures in the transferred handoff are producer evidence; this harness validates correctness and immutability, not a new production latency benchmark.

## Downstream contract

Future stages may assume:

1. Candidate identity is exactly `(infoHash,fileIndex)`; `null` is distinct from `0`.
2. Exact deduplication uses `releaseKey` only; hash/family/fuzzy equivalence is not exact identity.
3. Stage 3 produces an ordered candidate set based on static evidence, with deterministic tie ordering for a fixed corpus and scoring implementation.
4. Public pagination occurs after ranking.
5. No 2000-row or other unmeasured pre-rank truncation is safe for this measured query set.
6. Native behavior and frozen reference behavior are separate measurable contracts; fixture expectations do not silently redefine production semantics.
7. Provider/cache state is neither candidate identity nor Stage 3 static desirability evidence.
8. Final acquisition is downstream: ranked candidates plus fresh provider reality plus explicit fulfillment policy.
9. No Stage 3 result by itself claims cached, placed, exposed, bound, cataloged, or playable state.

Future stages may **not** assume exact equality between native and transferred reference winners, full-corpus representativeness, live/provider coverage, or episode-policy validation from these fixtures.

## Exit criteria

- PASS — fixture databases load deterministically.
- PASS — SHA-256 before/after proves source fixtures are not mutated.
- PASS — native runtime retrieval executes against actual fixture rows via an isolated writable copy.
- PASS — reference ranking executes against the source in read-only mode.
- PASS — native/reference mismatches are phase-attributed and the five named semantic cases are explained.
- PASS — the same 11-query retrieval-cap regression reproduces.
- PASS — the downstream static-ranking/provider-reality boundary is explicit.

No Sonarr, Radarr, Zurg, Real-Debrid, TorBox fulfillment, UI acquisition flow, or lifecycle automation was added.
