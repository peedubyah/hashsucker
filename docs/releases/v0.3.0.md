# HashSucker v0.3.0 — intent profiles, generic downloads, bounded retention

20 commits past v0.2.0. Same appliance, further up the product ladder:
households can now say what quality is good enough, stage anything for
an external importer through one generic door, and trust HashSucker to
stop paying disk rent after the importer confirms receipt. Install and
update per `UNRAID.md`.

## What improved

- **Named intent quality profiles.** `balanced` (today's behavior),
  `hd` (1080p-class terminal), `max` (quality over fragility) bound
  initial selection and autonomous upgrades through one vocabulary —
  never a DSL, never a ranking rewrite. Unknown names are a clear 400.
- **Generic staged downloads.** Any external system names the media;
  HashSucker resolves one exact TorrentFile and stages verified bytes
  for an external importer, with bounded retry and re-stage on re-POST.
  Profiles ride along with identical meaning as library requests.
- **Bounded post-consumption retention.** Completed handoffs schedule
  cleanup after a 1h grace, tied to the exact handoff version; already-
  moved files converge, unlink failures retry boundedly without media
  re-resolution, stale versions can never authorize deletion.
- **Autonomous quality-tier upgrades** with durability-confidence veto,
  temporary watch-once publications, Plex-session-aware retention, and
  bounded retry for download and promotion jobs.
- **Dual-provider coverage.** Cheap second-placement enrichment for
  published single-provider TorrentFiles plus storm-triggered
  resilience escalation.
- **Deployment path normalization.** Canonical `HASHSUCKER_*_HOST_PATH`
  variables are final leaf paths (compose never appends to them);
  leaf-style legacy values must be shadowed by explicit pins, or mounts
  resolve to doubled directories and services boot on empty state.
- **Cooperative corpus yielding** keeps Node responsive during ingestion.

## Upgrade

`docker compose pull && docker compose up -d` (atomic, all services).
Migrations are additive (new columns/tables only, backfills match empty
sets on first download use). Rollback is schema-safe; see `UNRAID.md`.
If `media-search` was started from a local build, re-pin to the release
(`docker compose pull` refreshes `:latest`) or keep the equivalent local
image — verify with `docker inspect` revision labels.
