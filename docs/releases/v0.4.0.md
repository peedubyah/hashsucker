# HashSucker v0.4.0 — appliance UI, quieter diagnostics, housekeeping

Short release past v0.3.0. The browser interface is now a finished
appliance surface instead of an operator workbench, the diagnostics
endpoint no longer turns UI polling into provider traffic, and proof
machinery has a labelled, boring cleanup path. Install and update per
`UNRAID.md`.

## What improved

- **Appliance web UI.** Seven intentional tabs (Overview, Activity,
  Library, Downloads, Providers, Diagnostics, Settings) replace the
  candidate picker and debug consoles. First-run state names exactly
  what is missing; failures speak plain language with technical detail
  behind expanders; every button maps to a genuine human decision.
- **Small operator API** (`/api/operator/activity|downloads|quality`,
  `POST /api/library/profile`, shared failure headlines) suitable for
  a future TUI. Read-mostly; no business logic duplicated.
- **Diagnostics probe caching** (60s): repeated loads share one probe
  set instead of re-hitting TorBox/Plex per poll.
- **Host housekeeping** (`scripts/hashsucker-housekeeping`): report by
  default; `--clean` removes only ownership-labelled disposables and
  aged scratch dirs. Images stay a human decision.
- **Path pins documented**: canonical `HASHSUCKER_*_HOST_PATH` leaf rule
  plus the importer pins that keep current mounts exact.

## Upgrade

`docker compose pull && docker compose up -d` (atomic, all services).
No migrations beyond additive columns/tables. Rollback is schema-safe;
see `UNRAID.md`.
